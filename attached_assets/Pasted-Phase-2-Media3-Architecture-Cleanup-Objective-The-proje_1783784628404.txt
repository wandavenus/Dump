Phase 2 — Media3 Architecture Cleanup

Objective

The project has already been migrated to a single Media3 playback engine.

This phase is NOT about adding new features.

Its purpose is to remove every remaining artifact from the previous hybrid-engine architecture and leave the codebase clean, consistent, and ready for future native modules.

---

1. Rename Legacy Components

Audit every class, file, method, variable, and comment.

Anything whose name still implies multiple playback engines should be renamed.

Examples:

- AudioEngineManager
- EngineManager
- EngineType
- PlaybackEngine
- EngineState
- EngineCallback

Rename them to terminology that reflects the current architecture.

Examples:

- PlaybackManager
- PlaybackController
- PlaybackBridge
- PlaybackState

Choose names based on actual responsibilities.

---

2. Remove Compatibility Stubs

Search for every compatibility layer created during the MediaKit removal.

Examples:

- no-op methods
- compatibility callbacks
- empty implementations
- deprecated wrappers
- temporary forwarding methods

If they are no longer required, remove them completely.

If any call sites still depend on them, refactor those call sites instead of keeping legacy APIs.

No compatibility layer should remain unless it has a real purpose.

---

3. Remove Legacy Multi-Engine Concepts

Search the entire repository.

Remove anything related to:

- engine switching
- engine selection
- playback engine preferences
- engine enums
- engine abstractions
- engine-specific conditions
- dead feature flags
- comments referring to hybrid architecture

There should be no remaining conceptual reference to multiple playback engines.

---

4. Audit Playback Flow

Verify the playback pipeline is now:

Flutter UI

↓

AudioService

↓

PlaybackManager

↓

Media3PlaybackBridge

↓

Media3PlaybackService.kt

↓

ExoPlayer

Ensure there are no unnecessary wrappers.

Remove redundant forwarding layers where appropriate.

---

5. Clean Naming

Standardize naming conventions across the audio module.

Avoid inconsistent naming such as:

Engine
Player
Bridge
Manager
Controller

Each component name should accurately describe its responsibility.

---

6. Audit Channels

Inspect all:

- MethodChannels
- EventChannels
- StreamControllers
- BroadcastStreams

Remove obsolete channels.

Verify every remaining channel is actively used.

---

7. Dependency Audit

Remove:

- unused imports
- unused utility classes
- obsolete helper methods
- dead constants
- legacy documentation
- obsolete TODOs

No dead code should remain.

---

8. Validation

Confirm:

- playback works
- queue works
- MediaSession works
- notification works
- Bluetooth works
- Android Auto support (if present) works
- crossfade works
- gapless works
- preload works
- artwork works
- audio focus works

Behavior must remain identical.

---

Deliverables

Provide:

1. All renamed files/classes.
2. All deleted compatibility layers.
3. Remaining technical debt.
4. Updated playback architecture diagram.
5. Recommendations before implementing the NativeBridge (C++ DSP + FFmpeg).
