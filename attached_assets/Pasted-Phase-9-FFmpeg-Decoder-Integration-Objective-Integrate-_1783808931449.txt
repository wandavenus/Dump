Phase 9 — FFmpeg Decoder Integration

Objective

Integrate FFmpeg into the existing native audio runtime as an optional decoder for audio formats that Media3 cannot decode natively.

FFmpeg is NOT a playback engine.

Media3 remains the only playback engine.

Do NOT replace Media3.

Do NOT bypass the existing DSP pipeline.

---

1. Decoder Selection

Implement automatic decoder selection.

Preferred order:

1. Media3 native decoder
2. FFmpeg decoder (fallback)

Media3 should always be preferred whenever it supports the format.

Only use FFmpeg when Media3 cannot decode the file.

---

2. Supported Formats

Focus on formats commonly unsupported or inconsistently supported by Media3.

Examples:

- ALAC
- AIFF
- APE
- WavPack
- Monkey's Audio
- TAK (if feasible)

Do not duplicate codecs already handled well by Media3.

---

3. PCM Output

FFmpeg must output PCM compatible with the existing DSP pipeline.

Do not create a separate processing path.

All decoded PCM must flow through the same Native DSP Pipeline.

---

4. Native Runtime

Integrate FFmpeg directly into native_audio_runtime.

Do not depend on deprecated FFmpegKit.

Keep FFmpeg modular so it can be updated independently.

---

5. PlaybackManager

Expose:

- active decoder
- decoder capabilities
- decoder fallback reason

PlaybackManager remains the only public API.

---

6. Error Handling

If FFmpeg also fails:

- provide a clear playback error
- never crash
- keep playback service alive

---

7. Performance

Avoid unnecessary copies.

Reuse existing PCM buffers whenever possible.

Keep decoder switching transparent.

---

8. Documentation

Document:

- decoder selection flow
- supported formats
- fallback mechanism
- PCM ownership
- integration with DSP pipeline

---

Validation

Verify:

- flutter analyze passes
- native runtime tests pass
- Media3 playback unchanged
- Crossfade still works
- Gapless still works
- Queue still works
- FFmpeg fallback works correctly
- DSP pipeline still processes FFmpeg-decoded PCM
- No regressions
