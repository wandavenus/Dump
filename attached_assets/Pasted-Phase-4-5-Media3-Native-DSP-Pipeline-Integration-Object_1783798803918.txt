Phase 4.5 — Media3 ↔ Native DSP Pipeline Integration

Objective

The Native DSP Core has been implemented.

Before adding more DSP processors (Parametric EQ, Compressor, Limiter, etc.), integrate the existing DSP pipeline into the actual Media3 playback path.

The goal of this phase is to prove that every sample played by Media3 can flow through the native DSP pipeline.

Do NOT implement additional DSP processors.

Do NOT implement FFmpeg.

Only integrate the existing DSP pipeline.

Media3 remains the only playback engine.

---

1. Integrate DSP Pipeline

Connect the existing Native DSP Pipeline into the Media3 playback path.

Do not create a parallel playback path.

Media3 must remain the playback engine.

The DSP pipeline becomes part of the playback pipeline.

---

2. PCM Flow

Verify that PCM produced during playback reaches the native DSP pipeline.

The pipeline must receive real playback data.

Avoid copies whenever possible.

Document the PCM ownership model.

---

3. Gain Processor Validation

The existing Gain Processor must process real playback audio.

Verify:

- 0 dB
- positive gain
- negative gain
- bypass
- enable / disable

Changes should affect actual playback.

---

4. Latency

Measure additional latency introduced by the DSP pipeline.

Target:

- minimal added latency
- no audible glitches
- no playback interruptions

---

5. Thread Safety

Ensure the DSP pipeline executes safely on the playback thread.

No blocking.

No heap allocations during processing.

No locks inside the processing loop.

---

6. Performance

Verify:

- zero unnecessary allocations
- zero-copy bypass
- reusable buffers
- cache-friendly memory layout
- SIMD-ready implementation

---

7. Playback Compatibility

Verify that the following continue working correctly:

- Crossfade
- Gapless playback
- Queue transitions
- Preload
- Seek
- Pause
- Resume
- Repeat
- Shuffle

Native DSP integration must not break existing Media3 features.

---

8. PlaybackManager

PlaybackManager remains the only public interface.

UI must never access the native runtime directly.

PlaybackManager owns:

- DSP enable / disable
- DSP parameters
- Processor status
- Capability queries

---

9. Documentation

Document:

- Media3 PCM flow
- Native DSP insertion point
- Thread ownership
- Audio buffer ownership
- Playback lifecycle
- Performance considerations

---

Validation

Verify:

- flutter analyze passes
- native runtime tests pass
- playback unchanged
- Media3 unchanged
- Crossfade still works
- Gapless still works
- Queue still works
- Gain Processor affects real playback audio
- No analyzer warnings
- No measurable performance regression

If Media3 cannot expose a suitable PCM processing hook:

Research the latest official Media3 / ExoPlayer documentation.

Implement the officially recommended integration point.

Avoid unsupported hacks.

Document the reasoning.
