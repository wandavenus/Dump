Phase 8 — ReplayGain Engine

Objective

Implement a production-quality ReplayGain playback engine.

ReplayGain must be metadata-based.

Do NOT modify audio files.

Do NOT implement loudness normalization yet.

Do NOT implement FFmpeg.

Media3 remains the playback engine.

---

1. ReplayGain Processor

Create a dedicated ReplayGain processor.

ReplayGain should operate as a transparent gain stage.

It must not modify source audio.

---

2. Metadata Support

Support:

- Track Gain
- Album Gain
- Track Peak
- Album Peak

Design the architecture so future metadata formats can be added easily.

---

3. Playback Modes

Support:

- ReplayGain Disabled
- Track Gain
- Album Gain
- Automatic mode

Automatic mode should choose the most appropriate metadata.

---

4. Clipping Protection

Implement optional clipping prevention.

Support:

- use peak metadata when available
- prevent digital clipping
- preserve dynamics

Avoid unnecessary attenuation.

---

5. PlaybackManager

Expose:

- ReplayGain mode
- ReplayGain enabled
- Clipping protection
- Metadata availability
- Active gain value

PlaybackManager remains the only public interface.

---

6. Metadata Integration

Research current Media3 capabilities.

If ReplayGain metadata is already available through Media3 extractors, reuse it instead of reparsing files.

Only implement custom metadata parsing if required.

Prefer official Media3 APIs whenever possible.

---

7. Thread Safety

Audio thread:

- no locks
- no heap allocations
- deterministic execution

Control thread:

- lock-free parameter updates

---

8. Documentation

Document:

- ReplayGain metadata
- Track vs Album Gain
- Peak handling
- Clipping prevention
- Processing order
