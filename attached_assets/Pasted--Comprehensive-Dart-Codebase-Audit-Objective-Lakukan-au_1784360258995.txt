# Comprehensive Dart Codebase Audit

## Objective

Lakukan audit menyeluruh terhadap seluruh kode Dart pada repository untuk mengidentifikasi masalah arsitektur, kualitas kode, performa, maintainability, serta menemukan seluruh dead code, file, folder, asset, dan dependency yang sudah tidak digunakan.

**Jangan melakukan perubahan apa pun terlebih dahulu. Fokus hanya pada audit dan pelaporan.**

---

# Scope

Audit seluruh project Flutter, termasuk namun tidak terbatas pada:

- `lib/`
- `test/`
- `integration_test/`
- `tool/`
- Seluruh file `.dart`

Jika terdapat folder Dart di luar lokasi tersebut, audit juga.

---

# Audit Checklist

## 1. Dead Code Analysis

Temukan seluruh kode yang sudah tidak pernah digunakan.

Periksa:

- Unused class
- Unused widget
- Unused function
- Unused extension
- Unused mixin
- Unused enum
- Unused typedef
- Unused constant
- Unused variable
- Unused model
- Unused service
- Unused repository
- Unused controller
- Unused helper
- Unused utility
- Unused provider
- Unused notifier
- Unused stream
- Unused callback

Untuk setiap temuan, pastikan benar-benar tidak memiliki referensi aktif di seluruh project.

---

## 2. Folder Audit

Cari folder yang:

- Sudah tidak digunakan
- Kosong
- Berisi file yang seluruhnya sudah tidak dipakai
- Bisa digabung dengan folder lain
- Tidak sesuai struktur project saat ini

---

## 3. File Audit

Cari file yang:

- Tidak pernah digunakan
- Tidak pernah di-import
- Sudah digantikan implementasi baru
- Masih tersisa dari refactor lama
- Duplicate implementation
- Experimental file yang terlupakan

---

## 4. Import Audit

Periksa:

- Unused import
- Duplicate import
- Circular import
- Import yang tidak diperlukan
- Relative import yang sebaiknya menggunakan package import (jika sesuai dengan standar project)

---

## 5. Architecture Audit

Cari:

- Code smell
- Circular dependency
- Tight coupling
- Duplicate logic
- God class
- God widget
- Massive file
- Over abstraction
- Under abstraction
- Layer violation
- Dependency yang salah arah

---

## 6. Flutter Best Practice

Periksa:

- Widget terlalu besar
- Build() terlalu kompleks
- Widget yang bisa dipecah
- State management yang kurang tepat
- Rebuild berlebihan
- Async misuse
- Future yang tidak ditangani
- Stream leak
- Animation yang berpotensi bermasalah

---

## 7. Performance Audit

Cari:

- Unnecessary rebuild
- Object allocation berlebihan
- Widget tree yang terlalu dalam
- Cache yang tidak efektif
- Repeated computation
- Inefficient collection operation
- Memory leak
- Listener yang tidak di-dispose
- Controller yang tidak di-dispose

---

## 8. Null Safety Audit

Periksa:

- Force unwrap yang tidak aman
- Nullable yang tidak diperlukan
- Null handling yang berpotensi crash
- Redundant null check

---

## 9. Naming Audit

Cari:

- Nama file tidak konsisten
- Nama class membingungkan
- Nama method tidak jelas
- Nama variable kurang deskriptif
- Penamaan yang tidak mengikuti standar Dart

---

## 10. Dependency Audit

Periksa apakah terdapat:

- Package yang sudah tidak digunakan
- Dependency transitif yang tidak diperlukan
- Import package yang sudah tidak pernah dipakai
- Utility internal yang sudah tergantikan

---

## 11. Asset Reference Audit

Periksa apakah terdapat:

- Asset yang sudah tidak pernah direferensikan
- Icon yang tidak digunakan
- Font yang tidak digunakan
- JSON yang tidak digunakan
- SVG yang tidak digunakan
- Image yang tidak digunakan

---

## 12. Routing Audit

Periksa:

- Route yang tidak pernah dipakai
- Screen yang sudah tidak bisa diakses
- Navigation yang sudah obsolete

---

## 13. Service Audit

Periksa:

- Service yang sudah tidak dipakai
- Singleton yang tidak pernah digunakan
- Repository yang tidak memiliki consumer
- Manager yang tidak pernah dipanggil

---

## 14. Public API Audit

Cari:

- Method public yang tidak pernah dipanggil
- API internal yang bisa dibuat private
- Export yang tidak diperlukan

---

## 15. Consistency Audit

Cari inkonsistensi seperti:

- Folder naming
- File naming
- Coding style
- Pattern yang berbeda untuk fungsi yang sama
- Struktur project yang tidak seragam

---

# Validation Rules

Sebelum menyatakan suatu kode sebagai dead code atau tidak terpakai:

- Lakukan pencarian referensi di seluruh project.
- Periksa seluruh import dan export.
- Periksa penggunaan melalui callback, generic, reflection, extension, provider, router, service locator, dependency injection, atau mekanisme lain yang dapat membuat simbol tetap digunakan.
- Jangan menghapus sesuatu hanya karena terlihat tidak dipakai.

Jika masih ada kemungkinan digunakan, tandai sebagai **Needs Manual Verification**, bukan sebagai dead code.

---

# Expected Output

Buat laporan audit yang dikelompokkan berdasarkan kategori.

Untuk setiap temuan sertakan:

- Severity
- File
- Line (jika relevan)
- Deskripsi masalah
- Alasan teknis
- Dampak
- Tingkat keyakinan (High / Medium / Low)
- Rekomendasi perbaikan

---

# Final Summary

Di akhir laporan tampilkan ringkasan seperti berikut:

- Total file Dart
- Total folder yang diaudit
- Total dead code
- Total unused file
- Total unused folder
- Total duplicate logic
- Total architecture issue
- Total performance issue
- Total maintainability issue
- Total potential bug
- Daftar prioritas perbaikan berdasarkan tingkat risiko

---

# Rules

- Jangan mengubah kode.
- Jangan menghapus file.
- Jangan membuat commit.
- Jangan melakukan refactor.
- Jangan memperbaiki masalah secara otomatis.
- Fokus hanya pada audit dan pelaporan.
- Gunakan bukti yang dapat diverifikasi dari source code.
- Jika ragu terhadap suatu temuan, tandai sebagai **Needs Manual Verification** daripada membuat asumsi.
