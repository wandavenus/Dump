# Objective

Implement a complete Light Mode for the application while preserving the existing Dark Mode.

The application already has its own design language and visual identity.

Do NOT redesign the UI to match Material Design or Material 3.

The goal is to keep the application's current appearance and behavior while making every screen work correctly in both Light Mode and Dark Mode.

---

# Architecture

Follow Flutter and Dart best practices.

Implement a centralized theme system.

Do not scatter colors throughout the project.

Create a dedicated theme structure.

Example

lib/
 └── theme/
      app_theme.dart
      app_colors.dart
      app_text_styles.dart
      theme_extensions.dart (only if necessary)

The entire application must obtain colors from the centralized theme.

---

# ThemeData

Use Flutter ThemeData only as the theme container.

Do not migrate the application to Material 3.

Do not redesign widgets.

Keep the existing visual language.

Configure

- theme
- darkTheme
- themeMode

Use ThemeMode.system by default.

The architecture must support

- Light
- Dark
- System

without further code changes.

---

# Color System

Remove hardcoded UI colors whenever possible.

Replace

Colors.black

Colors.white

Colors.grey

Color(...)

with semantic colors from the centralized theme.

Only media-related colors (album artwork, extracted palettes, waveform colors, visualizers, etc.) may remain dynamic.

---

# Typography

Centralize reusable TextStyles.

Avoid duplicated TextStyle definitions.

Widgets should obtain typography from the centralized theme.

---

# Custom Components

The application contains many custom widgets.

Update every custom widget so it adapts automatically to Light and Dark themes.

Avoid assumptions that the UI is always dark.

---

# Glass UI

The application uses custom glassmorphism.

Keep the same visual style.

Do NOT redesign it.

Only adjust

- background opacity
- overlay opacity
- border opacity
- shadow intensity
- blur tint

for Light Mode.

Maintain the same premium appearance.

---

# Backgrounds

Dark Mode should remain visually identical.

Light Mode should preserve the same hierarchy while using brighter surfaces.

Avoid pure white backgrounds unless intentionally required.

Prefer subtle off-white or lightly tinted surfaces that match the application's design language.

---

# Icons

Icons should automatically adapt to the active theme.

Avoid hardcoded icon colors.

---

# Animations

Do not modify existing animations.

No timing changes.

No behavioral changes.

---

# Performance

Do not recreate ThemeData inside build methods.

Keep themes immutable.

Avoid unnecessary rebuilds.

---

# Migration

Update the entire application.

Every screen should support

- Light Mode
- Dark Mode

consistently.

No page should remain dark-only.

---

# Cleanup

After migration

- remove duplicated colors
- remove obsolete constants
- remove unused theme code
- remove dead styling code

Run formatter.

Ensure analyzer introduces no new warnings.
