Phase 8.5 — Loudness Normalization Engine

Objective

Implement a production-quality Playback Loudness Normalization engine.

This feature is separate from ReplayGain.

ReplayGain uses metadata.

Loudness Normalization measures perceived loudness during playback and gently adjusts playback gain.

Do NOT implement dynamic range compression.

Do NOT replace ReplayGain.

Do NOT implement FFmpeg.

Media3 remains the playback engine.

---

1. Loudness Analyzer

Implement a native loudness analyzer based on the EBU R128 / ITU-R BS.1770 measurement model.

Design the architecture so it can be extended in the future.

Do not implement a simplified RMS normalizer.

Use perceptual loudness principles.

---

2. Playback Loudness Controller

Implement a playback loudness controller.

Responsibilities:

- analyze loudness
- calculate target gain
- smoothly apply gain changes
- avoid audible pumping
- preserve musical dynamics

The controller should never behave like an aggressive compressor.

---

3. Gain Smoothing

Implement smooth gain transitions.

Requirements:

- no clicks
- no zipper noise
- gradual adjustment
- stable playback

Avoid rapid gain oscillation.

---

4. Interaction with ReplayGain

ReplayGain remains the first normalization stage.

Loudness Normalization operates after ReplayGain.

If ReplayGain metadata is unavailable, Loudness Normalization should still function correctly.

The two systems must complement each other rather than conflict.

---

5. PlaybackManager

Expose:

- enable / disable
- target loudness
- current measured loudness
- applied gain
- analysis status

PlaybackManager remains the only public API.

---

6. Performance

Optimize for:

- minimal CPU usage
- reusable buffers
- lock-free parameter updates
- zero heap allocation inside the audio thread
- deterministic execution

---

7. Documentation

Document:

- EBU R128 / ITU-R BS.1770 design
- analyzer lifecycle
- gain controller
- smoothing algorithm
- processing order
- interaction with ReplayGain
