# Investigate Scroll Animation Stutter

Issue:

The small navigation title in the AppBar follows the large page title while scrolling.

There is NO noticeable FPS drop.

The entire UI remains smooth.

Only the small title movement looks slightly "stepped" or "not true 60 FPS".

This is suspected to be caused by an overly aggressive scroll optimization rather than rendering performance.

---

## Goal

Find the root cause.

Do NOT change code until the cause is confirmed.

---

## Investigate the complete scroll pipeline

Trace the entire path:

ScrollController

↓

NotificationListener / ScrollListener

↓

scrollOffsetListenable.value

↓

ValueListenableBuilder

↓

FadingTitleAppBar

↓

Transform.translate()

Verify every stage.

---

## Look specifically for

### 1.

Any throttling.

Examples:

- debounce
- throttle
- timer
- scheduleMicrotask
- postFrameCallback batching
- frame skipping

---

### 2.

Any update filtering.

Examples:

```dart
if ((offset - last).abs() > ...)
```

or

```dart
if (offset != previous)
```

or

```dart
epsilon
```

or

```dart
minimum delta
```

---

### 3.

Loss of precision.

Look for:

```dart
round()

floor()

ceil()

toInt()

truncate()

roundToDouble()
```

before assigning

```dart
scrollOffsetListenable.value
```

---

### 4.

Animation quantization.

Check whether the offset is snapped to fixed intervals.

---

### 5.

Multiple scroll sources.

Verify there is only ONE source updating the notifier.

---

### 6.

Frame timing.

Ensure notifier updates every scroll frame.

Not every N pixels.

---

### 7.

Animated widgets.

Verify that no:

- AnimatedPositioned
- AnimatedContainer
- AnimatedSlide
- AnimatedOpacity

are fighting against direct scroll updates.

---

### 8.

Check whether the title movement itself is mathematically smooth.

Current transform:

```dart
Transform.translate(...)
```

Verify the computed translation changes continuously for every scroll frame.

---

## If no issue is found

Profile the rebuild path.

Determine whether the AppBar rebuilds more than necessary.

Measure:

- rebuild count
- repaint count
- layout count

during scrolling.

---
