# Additional Architecture Requirements

Before implementing FFmpeg integration, research the latest official FFmpeg project documentation and current Android integration best practices.

Do not use deprecated or archived FFmpeg wrappers (such as FFmpegKit) unless there is a strong technical justification.

Prefer integrating FFmpeg directly into the existing `native_audio_runtime` package.

---

Research and justify the selected integration approach before implementation.

Compare available approaches, including:

- Direct FFmpeg native integration
- Official FFmpeg build system
- Modern actively maintained alternatives
- Existing Android best practices

Document why the chosen solution is the best fit for this project's architecture.

---

Do not duplicate Media3 functionality.

Media3 remains the primary playback engine.

FFmpeg exists only as an optional decoder for unsupported formats.

Never replace Media3 playback with FFmpeg playback.

---

Reuse the existing Native DSP Pipeline.

All PCM produced by FFmpeg must flow through exactly the same DSP chain used by Media3.

Do not create a second DSP implementation.

Do not duplicate audio processors.

---

Keep FFmpeg isolated behind a dedicated decoder module.

Future FFmpeg updates should require minimal changes to the rest of the project.

Avoid tight coupling between FFmpeg internals and PlaybackManager.

---

Implement automatic decoder selection.

Selection priority:

1. Media3 native decoder
2. FFmpeg decoder

Automatically fall back to FFmpeg only when Media3 cannot decode the media.

Fallback should be transparent to the user.

---

Research codec support before implementation.

Identify which formats Media3 already supports well and avoid routing those formats through FFmpeg unnecessarily.

Focus FFmpeg support on formats that Media3 cannot reliably decode.

---

Keep memory usage efficient.

Reuse PCM buffers whenever possible.

Avoid unnecessary memory copies between FFmpeg, the Native DSP Pipeline, and Media3.

---

Maintain compatibility with the existing playback architecture.

The following features must continue working regardless of which decoder is active:

- Crossfade
- Gapless playback
- Queue transitions
- ReplayGain
- Loudness Normalization
- Parametric EQ
- Compressor
- Crossfeed
- Limiter
- Soft Clipper

The decoder should become an implementation detail, invisible to the rest of the application.

---

If Android SDK/NDK compilation cannot be verified in the current environment:

Continue implementing the architecture.

Clearly document all assumptions.

Do not replace implementation with mock code.

Mark every unverified native integration point for later validation on a real Android toolchain.

---

Provide a final architecture review after implementation.

Evaluate:

- maintainability
- scalability
- decoder abstraction
- DSP integration
- future codec expansion
- potential performance bottlenecks
- remaining technical debt

Recommend any improvements before considering the audio architecture complete.
