# Phase 8B — Player Sheet Rendering Refactor

## Objective

Refactor the Player Sheet rendering architecture to reduce unnecessary widget rebuilds while preserving 100% identical behavior and visuals.

This is an architectural optimization.

NOT a UI redesign.

NOT a feature implementation.

---

# Scope

Only refactor the Player Sheet.

Examples include:

- Player Sheet
- Player Content
- Player Header
- Player Controls
- Progress Section
- Artwork Section
- Background
- Lyrics Overlay

Only where rebuild optimization is validated.

---

# Primary Goal

Reduce rebuild scope.

Every widget should rebuild ONLY when its own data changes.

Avoid rebuilding the whole Player Sheet.

---

# Rules

Do NOT change:

- animations
- gestures
- playback
- Media3
- ReplayGain
- DSP
- queue
- navigation

Behavior must remain identical.

---

# ValueListenableBuilder

Review every ValueListenableBuilder.

Determine:

- what value it listens to
- which widgets actually depend on that value

Reduce listener scope to the smallest possible subtree.

Never wrap the entire Player Sheet if only one widget changes.

---

# AnimatedBuilder

If AnimatedBuilder or similar builders rebuild excessive widget trees,

move static widgets into the child parameter whenever possible.

Avoid rebuilding constant UI.

---

# Artwork

Artwork updates must rebuild ONLY:

- artwork
- palette-dependent widgets

Not playback controls.

---

# Progress

Progress updates must rebuild ONLY:

- slider
- elapsed time
- remaining time

Do not rebuild artwork or controls every tick.

---

# Playback State

Play/Pause state changes should rebuild ONLY:

- play button
- state-dependent controls

Not unrelated widgets.

---

# Lyrics

Lyrics updates must rebuild ONLY:

- lyrics widgets

Not the entire sheet.

---

# Theme

Theme or palette updates should rebuild ONLY widgets that depend on theme colors.

---

# Widget Extraction

Extract widgets ONLY if it reduces rebuild scope.

Do not split files just to make them smaller.

Every extracted widget must have a clear rendering responsibility.

---

# Performance

Do not introduce:

- additional timers
- additional streams
- additional listeners
- duplicated ValueListenables

Keep listener count equal or lower.

---

# Validation

Run:

- flutter analyze

Verify:

- Player Sheet
- expand animation
- collapse animation
- drag gesture
- playback controls
- progress updates
- artwork updates
- lyrics
- palette animation
- background animation

Ensure all behavior remains identical.

---

# Deliverables

## Rendering Report

For each optimized widget:

- previous rebuild scope
- new rebuild scope
- reason

---

## Extracted Widgets

List every extracted widget and its responsibility.

---

## Listener Report

List:

- removed listeners
- retained listeners
- new listeners (if any)

New listeners should only exist when strictly necessary.

---

## Validation Report

Include:

- flutter analyze
- build status
- runtime verification

Stop after Player Sheet optimization.
