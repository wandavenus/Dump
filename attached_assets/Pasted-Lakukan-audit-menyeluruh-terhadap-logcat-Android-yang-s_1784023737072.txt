Lakukan audit menyeluruh terhadap logcat Android yang saya lampirkan.

Jangan hanya melihat baris yang berlabel Warning (W) atau Error (E). Analisis seluruh log secara kontekstual untuk menemukan akar masalah, bottleneck performa, bug tersembunyi, maupun warning yang sebenarnya normal.

Yang saya inginkan:

1. Kelompokkan semua temuan berdasarkan kategori:
   - Critical
   - High
   - Medium
   - Low
   - Normal / Expected

2. Untuk setiap temuan jelaskan:
   - arti log tersebut
   - penyebab paling mungkin
   - apakah berasal dari aplikasi saya, Android framework, Media3, FFmpeg, vendor Xiaomi/MIUI, Codec2, atau hardware
   - apakah aman diabaikan atau harus diperbaiki
   - dampaknya terhadap:
     - startup
     - scrolling
     - audio playback
     - seek
     - gapless
     - crossfade
     - artwork
     - notification
     - battery
     - memory
     - CPU
     - latency

3. Cari pola yang berulang.
   Contoh:
   - warning yang muncul berkali-kali
   - binder yang lambat
   - metadata yang dibaca berulang
   - artwork yang gagal dimuat
   - decoder yang terus diinisialisasi
   - codec yang dibuat berulang
   - object yang mungkin bocor

4. Fokus khusus pada:
   - Slow Binder
   - MediaMetadataRetriever
   - Codec2
   - FMQ
   - FFmpegLibrary
   - MediaSession
   - AudioTrack
   - AudioStreamTrack
   - ExoPlayer / Media3
   - MediaCodec
   - artwork loading
   - binder transaction
   - ANR risk
   - main thread blocking
   - unnecessary allocations
   - repeated initialization
   - excessive decoder creation

5. Tentukan apakah ada indikasi:
   - memory leak
   - resource leak
   - file descriptor leak
   - thread leak
   - bitmap leak
   - MediaMetadataRetriever leak
   - MediaCodec leak
   - AudioTrack leak
   - coroutine leak
   - repeated object creation

6. Cari peluang optimisasi:
   - mengurangi binder call
   - cache metadata
   - cache artwork
   - mengurangi MediaMetadataRetriever
   - mengurangi codec recreation
   - mengurangi bitmap decode
   - mengurangi GC pressure
   - mengurangi latency
   - mengurangi startup cost

7. Untuk setiap masalah yang ditemukan berikan:
   - lokasi kemungkinan di source code
   - prioritas perbaikan
   - solusi yang direkomendasikan
   - estimasi impact jika diperbaiki

8. Pisahkan mana yang:
   - benar-benar bug aplikasi saya
   - warning normal Android
   - warning khas Xiaomi/MIUI
   - warning Codec2 yang umum
   - warning Media3 yang normal
   - false positive

9. Jika ada log yang saling berhubungan, jelaskan hubungan sebab-akibatnya.

10. Di akhir buat tabel ringkasan:

| Severity | Log | Root Cause | Impact | Action |
|----------|-----|------------|--------|--------|

Lalu beri skor kesehatan logcat dari 0–100 beserta alasan penilaiannya.

Jangan berasumsi. Jika tidak yakin terhadap suatu log, jelaskan tingkat keyakinannya dan alasannya.
